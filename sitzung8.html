Sitzung 8: Digitale Repositorien und Software

Einleitung: In dieser Sitzung wurden Repositorien, DSpace und die langfristige Speicherung digitaler Daten kurz wiederholt. Danach wurden wichtige Standards, die Auswahl geeigneter Software, Softwarearchitektur und Projektmanagement behandelt.

Langfristige Verfügbarkeit

Digitale Daten bleiben nicht automatisch dauerhaft verfügbar. Server müssen betrieben, gepflegt und aktualisiert werden. Deshalb sollte ein Repositorium von einer zuverlässigen Organisation betreut werden.

Persistent Identifier, DOI, URL und URI

Eine URL zeigt den aktuellen Speicherort einer Ressource. Wird die Datei verschoben, kann die URL ungültig werden. Ein Persistent Identifier, zum Beispiel ein DOI oder Handle, bleibt gleich und wird mit der aktuellen Adresse verbunden. Eine URI identifiziert eine Ressource eindeutig; eine URL ist eine Form einer URI.

Standards für digitale Sammlungen

Gemeinsame Standards sorgen dafür, dass Daten zwischen verschiedenen Systemen ausgetauscht, gefunden und langfristig genutzt werden können.
OAI: entwickelt Standards für offene Repositorien.
DINI: bietet Kriterien für gute Repositorien in Deutschland.
Linked Open Data: verbindet Daten aus verschiedenen Quellen.
OAI-PMH: ermöglicht den automatischen Austausch von Metadaten.
OAI-ORE: beschreibt digitale Objekte, die aus mehreren Dateien bestehen.

Auswahl und Kosten einer Software

Eine Repository-Software muss zu den Anforderungen des Projekts passen. Wichtig sind aktuelle Standards, Datenschutz, Serverstandort, Erweiterbarkeit und technischer Support. Auch Open-Source-Software verursacht Kosten. Für den Betrieb werden Server, Installation, Wartung, Updates und Fachpersonal benötigt. Die größten Kosten entstehen deshalb oft durch den Betrieb und die Arbeitszeit.

Checksum

Eine Checksum wird aus dem Inhalt einer Datei berechnet. Wird die Datei verändert, entsteht normalerweise ein anderer Wert. Dadurch kann geprüft werden, ob eine Datei noch unverändert ist.

Softwarearchitektur

Beim Drei-Schichten-Modell werden die Aufgaben einer Software getrennt:
Storage Layer: Speicherung der Daten
Business Logic Layer: Verarbeitung der Daten
Application Layer: Darstellung für die Nutzerinnen und Nutzer
Diese Trennung macht die Software flexibler. Einzelne Bereiche können später verändert werden, ohne das gesamte System neu zu entwickeln.

API und Zukunftssicherheit

Eine API verbindet die verschiedenen Bereiche einer Software und legt fest, wie Daten zwischen ihnen übertragen werden. Bleiben diese Schnittstellen gleich, können einzelne Bausteine einfacher ersetzt werden. Dadurch bleibt die Software länger nutzbar und zukunftssicher.

Datenmodell und Softwarearchitektur

Das Datenmodell beschreibt die Organisation der Daten. Die Softwarearchitektur beschreibt den Aufbau und die Zusammenarbeit der technischen Teile einer Software.

Wasserfallmodell und agiles Vorgehen

Beim Wasserfallmodell wird das Projekt am Anfang möglichst vollständig geplant und danach Schritt für Schritt umgesetzt. Änderungen während des Projekts sind schwierig. Beim agilen Vorgehen wird das Projekt in kleine Schritte geteilt. Nach jedem Schritt wird Feedback eingeholt. Diese Methode benötigt mehr Kommunikation, führt aber oft zu einem Ergebnis, das besser zu den Bedürfnissen der Nutzerinnen und Nutzer passt.

Fazit

Ein digitales Projekt muss nicht nur technisch funktionieren, sondern auch langfristig geplant werden. Dauerhafte Identifier, aktuelle Standards, geeignete Software, eine flexible Architektur und regelmäßiges Feedback helfen dabei, digitale Inhalte sicher und dauerhaft nutzbar zu machen.
